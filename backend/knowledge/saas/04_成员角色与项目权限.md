# 成员角色与项目权限管理指南

## 1. `admin`、`member`、`guest` 三种角色的具体权限边界是什么？

在协作平台中，每个用户在工作空间（`workspace`）内都拥有唯一的空间成员角色（`membership`），分别为 **工作空间管理员（`admin`）**、**正式成员（`member`）** 和 **访客（`guest`）**。同时，在具体项目（`project`）内还设有四个细粒度权限等级：**只读查看（`read`）**、**可批注（`comment`）**、**可编辑（`edit`）** 和 **项目负责人/管理（`manage`）**。

以下权限矩阵完整说明了三种工作空间角色在项目访问、文档协作、成员管理、安全审计及 API 调用上的准确边界：

| 权限维度 / 具体操作项 | 管理员（`admin`） | 正式成员（`member`） | 访客（`guest`） | 核心规则与限制条件 |
| :--- | :--- | :--- | :--- | :--- |
| **访问本空间公开项目（`workspace_public`）** | 默认全部可访问并管理 | 默认全部可访问 | **默认不可见**（仅明确授权后可访问） | `guest` 不会因加入工作空间而自动看到公开项目 |
| **访问本空间私有项目（`private`）** | **默认全部可访问并管理** | 仅本人创建或已获授权的私有项目可访问 | 仅已获明确授权的私有项目可访问 | `admin` 管理本空间全部公开与私有项目，无需逐个申请私有项目 `read` 权限 |
| **创建新项目** | 允许 | 允许 | **禁止** | 创建入口位于 **「项目中心 > + 新建项目」** |
| **创建与协同编辑项目内文档（`edit`）** | 允许（本空间全部项目） | 允许（在拥有 `edit`/`manage` 权限的项目中） | **禁止**（不编辑项目主体与文档正文） | `member` 若在某项目中仅被授予 `read` 或 `comment`，则不可编辑该项目的文档；`guest` 不允许获得 `edit` 或 `manage` |
| **在项目文档中留批注与讨论（`comment`）** | 允许 | 允许（拥有 `comment`/`edit`/`manage` 时） | 允许（**仅当被授予 `comment` 权限时**） | **`read` 权限仅限只读浏览，不自动包含批注、编辑或删除权限**；`guest` 最高仅可获得 `comment` |
| **删除他人创建的项目或核心文档** | 允许（具备全局管理权） | **禁止**（仅可管理本人负责的资源） | **禁止** | 普通 `member` 不可随意删除他人项目或核心文档 |
| **共享项目/文档及调整项目可见范围** | 允许（可任意调整公开/私有及协作者） | 仅可在已有权限内分享链接（负责人可管本项目） | **禁止**（不扩大共享范围） | 普通 `member` 分享链接不能突破项目已有权限边界 |
| **跨部门接管项目** | **允许** | 禁止 | 禁止 | 入口位于 **「空间管理 > 项目全局管理 > 接管项目」** |
| **邀请/移除空间成员与分配角色** | **允许** | 禁止 | 禁止 | 入口位于 **「空间管理 > 成员与邀请」** |
| **发起与审批项目 `read` 访问申请** | 无需申请本空间项目；**可审批本空间所有项目申请** | 可对未授权私有项目发起 `read` 申请；**作为项目负责人时仅可审批自己负责的项目** | 可对未授权公开/私有项目发起 `read` 申请；无审批权 | 在线申请默认授予项目 `read` 权限，不支持在线申请提权为 `admin` |
| **管理项目安全设置与查看审计记录** | **允许** | 禁止 | 禁止 | 入口位于 **「空间管理 > 安全与审计日志」** |
| **调用固定产品 API 读取项目** | 具备本空间全部项目资源权限，**但仍须满足凭据 `project:read` 等条件** | 须同时满足凭据 `project:read` 与本人对该项目的访问权限 | 须同时满足凭据 `project:read` 与本人对该项目的明确授权 | 任何角色（含 `admin`）凭据缺少 `project:read` 均会返回 HTTP `403` |
| **跨租户（`tenant`）访问他方企业资源** | **严禁** | **严禁** | **严禁** | 跨租户访问在网页端与 API 端均被直接拒绝 |

## 2. 为什么正式成员（`member`）或访客（`guest`）看不到某个项目？如何申请访问？

### 2.1 项目不可见的三种常见原因
当你已登录工作空间，但在 **「项目中心」** 看不到某个目标项目时，通常由以下原因引起：
1. **你是正式成员（`member`），而目标项目是私有项目（`private`）**：`member` 仅默认可见公开项目（`workspace_public`），未加入私有项目协作者名单前无法直接看到该项目。
2. **你是访客（`guest`），尚未获得该项目的明确授权**：`guest` 对本工作空间的公开项目（`workspace_public`）和私有项目（`private`）均无默认可见权，只有被单独授权的项目才会显示。
3. **该项目属于其他企业租户（`tenant`）**：受企业级数据隔离限制，任何跨租户项目均不可查看，也无法发起权限申请。

### 2.2 `member` / `guest` 申请项目访问权限的操作步骤
- **适用角色**：对本工作空间内目标项目尚未获得访问权限的 `member` 或 `guest`。
- **前提条件**：已向同事获取目标项目的准确项目标识（`project_id`，如 `proj_sec_2026`）或项目分享链接，且该项目属于当前所在工作空间。
- **页面路径与操作方式**：
  - **在协作平台页面发起申请（唯一正式提交入口）**：
    1. 点击左侧导航栏 **「项目中心」** 右上角的 **「申请访问项目」** 按钮（或直接点击他人发来的项目分享链接进入“无访问权限”引导页并点击 **「申请只读访问（`read`）」**）。
    2. 填写或核对目标项目的 `project_id`，申请权限等级默认固定为 **「只读查看（`read`）」**，在说明框中填写申请理由（如“需查阅接口联调文档”）。
    3. 点击页面上的 **「提交申请」** 按钮完成提交。
  - **通过 Ordo 智能支持中心了解申请步骤或整理申请理由（辅助指导）**：
    1. 若你不清楚去哪里申请或如何表述申请背景，可打开右上角 **「帮助与支持 > Ordo 智能支持中心」**，向助手说明你的角色与需要访问的项目背景。
    2. Ordo 会为你讲解上述页面申请路径，并根据你提供的背景帮你拟定一段简明的申请理由文本。
    3. 你可复制该段申请理由，前往 **「项目中心 > 申请访问项目」** 页面粘贴并点击 **「提交申请」**（注：Ordo 助手不实时查询后台项目记录，也不会在聊天窗内替你生成卡片或代为提交申请）。
- **预期结果**：在平台页面点击 **「提交申请」** 后，正式生成状态为 **`submitted`（已提交待审批）** 的权限申请记录。你可以在顶部导航栏 **「帮助与支持 > 我的申请」** 页面查看审批进度。
- **关键注意事项**：
  - **“已提交（`submitted`）”不等于“已获授权（`approved`）”**：提交申请后你不会立刻获得项目访问权，必须等待**本工作空间管理员（`admin`）或该项目负责人（`manage`）**审批通过、状态变为 `approved` 后，授权才会真正生效。
  - **`read` 权限不包含批注或编辑能力**：审批通过后默认授予的是 `read`（只读查看）权限；如果你后续需要在文档上留批注（`comment`）或编辑文档（`edit`，仅限 `member`，不对 `guest` 开放），请联系该项目负责人或本空间 `admin` 在项目内的 **「项目成员与权限」** 页签手动调整你的权限等级。

## 3. 工作空间管理员（`admin`）或项目负责人如何审批项目权限申请？

- **适用角色与审批权限边界**：
  - **工作空间管理员（`admin`）**：可审批本工作空间内**所有公开或私有项目**的访问申请，操作入口位于左侧导航栏 **「空间管理 > 权限审批中心」**。
  - **项目负责人（拥有该项目 `manage` 权限的 `member` 或 `admin`）**：**仅可审批自己所负责的那个项目**的访问申请（不能审批其他项目的申请），操作入口位于 **「项目详情页 > 项目成员与权限 > 待审批申请」**。
- **前提条件**：目标项目存在状态为 `submitted`（已提交待审批）的项目访问申请。
- **操作步骤**：
  1. **管理员全局审批**：使用 `admin` 账号点击左侧导航栏 **「空间管理 > 权限审批中心」**；**项目负责人单项目审批**：进入本人负责的项目详情页，点击 **「项目成员与权限 > 待审批申请」**。
  2. 在 **「待审批（`submitted`）」** 列表中，核对申请人的姓名、当前空间角色（`member` 或 `guest`）、申请访问的目标项目（`project_id` 与项目名称）、申请权限等级（`read`）及申请说明。
  3. 根据业务协作需要执行审批操作：
     - **同意授权**：点击右侧 **「批准」** 按钮，申请状态更新为 **`approved`（已批准）**，系统自动将该申请人加入目标项目的协作者列表（授予 `read` 权限）。
     - **不予授权**：点击右侧 **「拒绝」** 按钮，填写拒绝说明并确认，申请状态更新为 **`rejected`（已拒绝）**，目标项目权限不做变更。
- **预期结果**：审批结果即时生效并写入审计日志（`audit_events`）。
  - **网页端访问验证**：申请状态变为 `approved` 后，申请人刷新 **「项目中心」** 页面即可打开并只读浏览该项目。
  - **API 调用验证提示**：项目授权批准（`approved`）仅代表该用户在业务上已具备该项目的 `read` 访问权，**不直接等同于 API 调用必定返回 `200 OK`**；若申请人需通过 API 读取该项目，仍需确保所使用的 API 凭据真实有效、已勾选 `project:read` 权限范围且工作空间当日调用配额充足，再使用原调用身份与原凭据复测并观察返回结果。
- **失败时的处理方法**：
  - **点击「批准」时提示“申请人已不在当前工作空间或已被移除”**：说明该申请人在提交申请后已被移出空间，系统自动阻止对失效主体的授权写入。

## 4. 管理员（`admin`）如何跨部门接管项目并调整项目访问范围？

当原项目负责人离职、转岗，或某个项目需要根据公司安全要求统一收紧/放开可见范围时，工作空间管理员（`admin`）可以直接接管项目并调整其访问范围。

- **适用角色**：仅工作空间管理员（`admin`）。
- **前提条件**：目标项目归属于当前所在企业租户的工作空间（不支持跨租户接管其他企业的项目）。
- **页面路径与按钮**：左侧导航栏 **「空间管理 > 项目全局管理」** → 目标项目操作列 **「接管项目」** / **「调整可见范围」**。
- **操作步骤**：
  1. 在左侧导航栏点击 **「空间管理 > 项目全局管理」**，页面会列出本工作空间下的**全部公开项目（`workspace_public`）与全部私有项目（`private`）**。
  2. **跨部门接管项目**：
     - 通过搜索框或部门筛选找到目标项目，点击该项目右侧操作列的 **「接管项目」** 按钮。
     - 在弹出的配置框中，选择 **「由我本人接管为项目负责人」** 或 **「指定本空间另一名正式成员（`member`）/管理员（`admin`）作为新负责人」**，并选择对原负责人的权限保留策略（保留为 `edit` 协作者或移出项目）。
     - 点击 **「确认接管」**，项目负责人（`manage`）即刻完成交接。
  3. **调整项目访问范围（公开/私有切换及协作者调整）**：
     - 在 **「空间管理 > 项目全局管理」**（或直接点进该项目的 **「项目设置」** 页签），点击 **「调整可见范围」**。
     - 将项目在 **「团队公开（`workspace_public`）」** 与 **「私有项目（`private`）」** 之间切换：
       - 若从 `workspace_public` 改为 `private`：除空间 `admin` 及该项目 **「项目成员与权限」** 列表中已显式添加的协作者外，其他普通 `member` 将不再默认看到该项目。
       - 若从 `private` 改为 `workspace_public`：本工作空间内的全体 `admin` 与 `member` 将立即获得该项目的默认访问权（注：`guest` 仍不会自动可见）。
     - 点击 **「保存设置」** 完成调整。
- **预期结果**：项目归属权与可见范围立即更新，无需原项目负责人手动配合即可完成跨部门资产交接与权限收敛。
- **失败时的处理方法**：
  - **在下拉框中无法将某用户指定为新项目负责人**：请检查该用户的空间角色是否为访客（`guest`）。`guest` 角色最高仅支持获得 `comment`（可批注）权限，不能担任项目负责人（`manage`）或拥有编辑权（`edit`）。

## 5. 管理员（`admin`）如何配置项目安全设置与查看审计记录？

- **适用角色**：仅工作空间管理员（`admin`）。
- **前提条件**：已登录目标工作空间的 `admin` 账号。
- **页面路径与按钮**：左侧导航栏 **「空间管理 > 安全与审计日志」**。
- **操作步骤**：
  1. 点击左侧导航栏 **「空间管理 > 安全与审计日志」**，默认显示 **「安全策略设置」** 与 **「权限与项目审计记录」** 两个页签。
  2. **配置项目安全设置**：在 **「安全策略设置」** 页签，管理员可配置：
     - **新建项目默认可见性**：设置空间内成员新建项目时默认勾选 `private` 还是 `workspace_public`。
     - **访客（`guest`）权限上限管控**：确认并锁定 `guest` 在任何项目中的最高权限不得超过 `comment`（禁止授予 `edit` 或 `manage`）。
     - 点击 **「保存安全设置」** 使策略生效。
  3. **查询与核对审计记录**：切换至 **「权限与项目审计记录」** 页签，可按时间范围、操作人、事件类型（项目创建、项目接管、可见性变更、成员邀请/移除、角色修改、权限申请审批 `approved`/`rejected`）及目标 `project_id` 进行筛选，查看每条审计事件的操作时间、操作人身份、变更前后的状态对比。
- **预期结果**：全面追溯本工作空间内所有敏感权限变动与项目交接历史，满足企业内部合规审计要求。

## 6. 示例：原项目负责人转岗后，管理员接管项目并调整团队权限

> **示例说明（以下为假设情境，仅供演示权限规则与操作方法，非当前用户真实状态）**：  
> **前提设定**：假设在“华盛制造”工作空间中，原供应链项目组长周工（`member`）调任其他事业部，其名下负责的私有项目“供应商评估系统（`proj_scm_2026`）”需要交接给新任组长郑工（`member`），同时要求外部审计顾问刘老师（`guest`）仅能阅读不能修改。

1. **空间管理员直接跨部门接管并转交项目**：工作空间管理员陈总监（`admin`）无需等待周工操作，直接进入 **「空间管理 > 项目全局管理」**，找到私有项目 `proj_scm_2026`（`admin` 对本空间所有私有项目天然拥有管理权），点击 **「接管项目」**，将新项目负责人指定为郑工（`member`），并将原负责人周工的权限降为只读（`read`）。
2. **新负责人审批成员申请并配置访客只读权限**：团队成员小孙（`member`）在 **「项目中心 > 申请访问项目」** 页面提交了 `proj_scm_2026` 的 `read` 权限申请（状态为 `submitted`）。郑工接管项目成为新负责人（`manage`）后，直接在该项目的 **「项目成员与权限 > 待审批申请」** 页签点击 **「批准」**（状态变为 `approved`），小孙即可访问该项目。同时，郑工点击 **「+ 添加协作者」** 将外部审计顾问刘老师（`guest`）加入项目，权限等级设为 **「只读查看（`read`）」**。由于 `read` 权限不自动包含批注、编辑或删除权限，刘老师登录后仅可浏览项目文档，无法修改任何内容或添加批注。
3. **审计留痕核验**：陈总监在 **「空间管理 > 安全与审计日志 > 权限与项目审计记录」** 中按 `proj_scm_2026` 筛选，即可清晰查看到“项目负责人变更为郑工”、“批准小孙 `read` 权限申请”及“新增协作者刘老师（`read`）”的完整审计记录。

## 7. 常见问题（FAQ）

### 问：我是工作空间管理员（`admin`），访问本空间里别人创建的私有项目（`private`）还需要先提交 `read` 权限申请吗？
答：不需要。在协作平台中，工作空间管理员（`admin`）负责管理本工作空间的全部公开项目与私有项目及相关文档，天然具备本空间内所有私有项目的访问、管理与接管权限，无需提交项目 `read` 权限申请。但请注意两条边界：（1）`admin` 严禁跨租户访问其他企业的项目；（2）当 `admin` 使用 API 凭据调用 `GET /sandbox/product/v1/projects/{id}` 时，所使用的 API 凭据本身仍必须勾选 `project:read` 权限范围（`scope`）且配额可用，否则接口仍会因凭据缺少 `scope` 或配额受限而报错。

### 问：外部访客（`guest`）已经拿到了某个项目的 `read` 权限，为什么还是不能在文档里留批注或改错别字？
答：因为协作平台严格限制访客（`guest`）的权限边界，且 **`read`（只读查看）权限不自动包含批注、编辑或删除权限**。首先，`guest` 在任何情况下都不允许编辑项目主体内容或文档正文（不支持授予 `edit` 或 `manage`）；其次，如果希望该 `guest` 在文档上留批注，需要由该项目负责人（`manage`）或本工作空间管理员（`admin`）进入该项目的 **「项目成员与权限」** 页面，将其权限等级从 `read` 显式调整为 **「可批注（`comment`）」**。
