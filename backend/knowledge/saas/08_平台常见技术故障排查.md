# 平台常见技术故障排查

本文档面向协作平台用户，提供以下四类常见技术与协作异常的排查方法：**页面加载与访问异常**、**文件上传与下载失败**、**文档保存与协同不同步**、**通知与协作提醒未收到**。遇到问题时，请对照你看到的现象，按从低风险到进一步检查的顺序逐步缩小范围。

## 1. 页面加载与访问异常（页面空白、持续加载、按钮无反应、项目或文档打不开）

### 1.1 你可能看到的现象
- 打开协作平台或点击某个项目、文档链接后，页面长时间显示空白（白屏）、加载图标一直转圈（持续加载中），或提示加载超时。
- 进入 **「项目中心」**、**「项目详情页」** 或 **「空间管理后台」** 时，页面提示“无法访问”“未找到资源”，或页面上的 **「+ 新建项目」**、**「+ 新建文档」**、**「添加批注」** 等按钮置灰、点击无反应。

### 1.2 需要区分的条件与尚未核实的可能原因
页面“打不开”或“按钮点不动”并不一定代表平台服务故障，也不一定全部属于权限不足。在排查前，需要将以下两类尚未核实的可能原因区分开来：

1. **登录账号、工作空间归属或角色权限条件不匹配（业务访问边界）**：
   - 当前登录的账号未切换到目标企业租户（`tenant`）对应的工作空间（`workspace`），或尝试访问了其他企业租户的资源（平台严禁任何角色跨租户访问，工作空间管理员 `admin` 的管理范围也仅限于本工作空间）。
   - 当前账号在工作空间中的角色与项目可见性不匹配：例如正式成员（`member`）默认仅可见公开项目（`workspace_public`），访问未获授权的私有项目（`private`）会受阻；访客（`guest`）仅能访问明确授权给自己的项目（公开项目也不默认可见）。
   - 按钮置灰或无法点击是因为权限等级限制：例如 `guest` 不允许创建新项目，且在项目内最高仅可获得 `comment`（可批注）权限，无法获得 `edit`（可编辑）或 `manage`（项目管理）权限；任何角色若在项目中仅拥有 `read`（只读查看）权限，其编辑与批注按钮均不可用（`read` 不自动包含批注、编辑或删除权限）。
   - 用户自述“我是管理员”或“我有权限”仅可作为初步分析条件，不能直接视为已核验事实，仍需在页面上核对当前实际生效的登录身份与授权记录。
2. **本地网络、浏览器缓存、扩展程序或会话状态异常（客户端与网络环境）**：
   - 本地网络连接波动，或网络访问策略影响了前端静态资源请求。
   - 浏览器安装的扩展程序影响了页面组件渲染或交互事件。
   - 浏览器本地缓存数据冲突，或当前网页登录会话（`/auth/login`）状态异常。

### 1.3 排查步骤、结果观察与下一步指引

#### 第一步：核对当前登录身份、所属工作空间与角色标签
- **适用条件**：所有遇到项目找不到、链接打不开或功能菜单缺失的用户。
- **操作方法**：查看页面顶部导航栏左上角的 **「工作空间切换器」**，以及右上角的 **「个人头像 > 账号与身份」**。
- **观察结果与下一步**：
  - **结果 A：当前显示的工作空间并非目标项目所在空间，或登录错了账号** → 在 **「工作空间切换器」** 下拉菜单中切换至目标工作空间，或退出后使用正确的企业账号重新登录。若下拉列表中没有目标空间，需联系该空间的 `admin` 在 **「空间管理 > 成员与邀请」** 中核对你的受邀状态。
  - **结果 B：工作空间正确，但页面明确显示“无访问权限”或按钮旁带有只读/权限限制提示** → 属于正常权限拦截而非页面故障。
    - 若需查看未授权项目：请在 **「项目中心 > 申请访问项目」** 页面输入目标 `project_id` 发起只读访问（`read`）申请，等待本工作空间 `admin`（在 **「空间管理 > 权限审批中心」**）或该项目负责人（在该项目 **「项目成员与权限 > 待审批申请」**，仅限审批本人负责的项目）批准为 `approved`。
    - 若需解除按钮置灰（如从 `read` 升级为 `comment` 或 `edit`）：请联系该项目负责人或本空间 `admin` 在 **「项目详情页 > 项目成员与权限」** 页面调整（注意：`guest` 最高仅可调整为 `comment`，不可授予 `edit` 或 `manage`）。
  - **结果 C：确认空间与权限均无误，但页面仍然白屏、一直转圈或点击按钮毫无反应** → 继续执行第二步。

#### 第二步：使用浏览器无痕/隐私窗口进行对比排查
- **适用条件**：已确认账号与权限正常，但页面渲染空白、样式错乱或按钮点击无响应（若当前页面有正在编辑但未保存的文档内容，请先参考本文第 3 节备份文本后再操作）。
- **操作方法**：打开浏览器的“无痕模式（Incognito）”或“隐私窗口”，使用同一企业账号登录协作平台并切换至同一工作空间，打开同一页面观察。
- **观察结果与下一步**：
  - **结果 A：无痕窗口中页面加载与按钮点击恢复正常** → 提示问题可能与原浏览器窗口的扩展程序、本地缓存、站点存储状态或会话差异有关，尚不能据此直接确认单一根因。请回到常规窗口按单变量顺序逐项核对：（1）先确认常规窗口与无痕窗口登录的是否为同一账号与同一工作空间；（2）在保持其他设置不变的前提下，先临时禁用浏览器扩展程序后刷新观察；（3）若禁用扩展后仍异常，再在确认无未保存文档内容的前提下清理当前站点缓存数据后重新登录核验。
  - **结果 B：无痕窗口中依然白屏或持续加载失败** → 继续执行第三步。

#### 第三步：记录具体失败请求并在合规条件下对比网络环境
- **适用条件**：常规窗口与无痕窗口均无法正常加载页面。
- **操作方法**：
  1. 优先记录页面显示的错误提示，或打开浏览器开发者工具（按 `F12` 切至 `Network` / 网络面板）刷新页面，观察失败请求的具体路径、请求类型与 HTTP 状态码（如 `Failed`、`Timeout`、`401` 或 `5xx`）。
  2. 在符合所在组织网络与安全规范的前提下，测试访问其他常规网页或在允许的测试网络环境下进行对比（注意：**请勿擅自关闭企业受管代理、企业 VPN、访问控制或终端安全防护软件**；若确需排查个人自行配置的代理工具，仅在本人有权调整且符合组织规则的条件下进行单项测试，并在测试后及时恢复原配置）。
- **观察结果与下一步**：
  - **结果 A：在允许的对比网络环境下或调整个人自配代理后恢复正常** → 提示问题可能与原网络链路或个人代理配置存在关联，尚不能仅凭一次切换定位到具体网络层级；可记录原网络下的失败请求特征，按组织网络规范核查配置。
  - **结果 B：开发者工具中观察到请求返回 `401`** → 需先区分该请求所属的接口类型，不能将所有 `401` 一律视为网页登录会话过期：
    - 若页面弹出未登录提示，或网页会话认证请求（如 `/auth/me`）返回 `401`，提示当前网页登录会话可能已失效，可通过 `/auth/login` 重新登录验证；
    - 若是在调用固定产品 API（`GET /sandbox/product/v1/me`、`GET /sandbox/product/v1/projects`、`GET /sandbox/product/v1/projects/{id}`）时返回 HTTP `401`（`UNAUTHORIZED`），则属于 API 凭据认证问题，请参考《05_API接入指南与接口说明.md》与《06_API错误排查手册.md》的“3. 调用接口返回 HTTP 401（UNAUTHORIZED）如何排查？”核对 `Authorization` 请求头与 API 凭据状态；
    - 若仅个别其他子资源请求返回异常状态码，请记录该请求路径与状态码以便进一步排查。
  - **结果 C：经上述核查后仍持续加载失败或返回服务端异常状态码** → 请保留脱敏诊断信息并前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面反馈。

### 1.4 仍未解决时建议保留的脱敏信息
若完成上述步骤后页面仍无法加载，请记录以下脱敏信息以便提交支持工单或向 **Ordo 智能支持中心** 咨询分析：
- 出现问题的具体页面路径或功能模块名称（如 **「项目中心」** 或 **「空间管理 > 项目全局管理」**）；
- 所属工作空间标识（`workspace_id`）、目标项目标识（`project_id`）及你在页面上看到的角色徽标（`admin` / `member` / `guest`）；
- 问题发生的时间点、浏览器名称及版本号、页面显示的完整报错提示文字（或开发者工具中的失败请求路径、HTTP 状态码与 `request_id`）；
- **安全提醒**：切勿在截图或文字中包含账号密码、Cookie 或完整的 API 明文令牌（`credential_token`）。

### 1.6 常见问题（FAQ）

#### 问：我是工作空间管理员（`admin`），为什么点进同事发来的一个项目链接还是提示“未找到该项目或无法访问”？你能帮我查一下后台日志吗？
答：Ordo 智能支持中心不直接读取后台日志或实时验证你的账号状态，但你可以按以下两点自行定位：
1. **核对是否跨租户**：`admin` 虽然管理本工作空间的全部公开项目（`workspace_public`）与私有项目（`private`），但管理范围严格限于本工作空间，**不允许跨租户（`tenant`）访问其他企业的项目**。如果同事发来的是另一家企业租户下的项目链接，系统会直接拒绝访问。
2. **核对当前选中的工作空间与 `project_id` 格式**：请在左上角 **「工作空间切换器」** 确认已切入目标空间，并进入左侧 **「空间管理 > 项目全局管理」** 搜索该项目的 `project_id`（合法格式为 `proj_` 开头的小写字母、数字或下划线，长度 8～32 位），确认该项目是否已被删除或拼写有误。

## 2. 文件上传与下载失败（上传进度停滞、上传报错中断、点击下载无响应）

### 2.1 你可能看到的现象
- 在项目或文档中上传附件/资料时，上传进度条长时间卡在某一百分比（上传进度停滞），或直接弹窗提示“上传失败”。
- 点击项目文档中的附件或导出文件时，页面没有任何反应（下载无响应），或浏览器提示下载被阻止、文件中断。

### 2.2 需要区分的条件与尚未核实的可能原因
文件上传或下载异常可能涉及权限、文件本身属性、网络传输或浏览器安全提示，请先区分以下三类待核实条件：

1. **当前账号在目标项目中的操作权限条件**：
   - **上传需具备编辑或管理权限**：只有工作空间管理员（`admin`）以及在该项目中拥有 **「可编辑（`edit`）」** 或 **「项目负责人/管理（`manage`）」** 权限的正式成员（`member`），才能向项目文档中上传或修改文件。
   - 若你在该项目中仅拥有 **「只读查看（`read`）」** 或 **「可批注（`comment`）」** 权限（特别是访客 `guest`，其最高权限上限为 `comment`，不允许获得 `edit` 或 `manage`），则无法执行上传写入操作。
   - 若在尝试下载时，你的项目访问权限已被移除或登录会话异常，下载请求也会被拦截。
2. **本地文件自身状态与页面规则提示**：
   - 待上传的本地文件正在被本地办公软件独占打开锁定、文件路径已变更、文件大小为 0 字节（空文件）或无法正常读取。
   - 文件触发了页面校验限制（如文件名包含特殊非法字符，或页面提示文件格式/大小不符合当前上传组件要求）。
3. **网络连接波动与浏览器下载拦截提示**：
   - 文件传输过程中发生网络波动或连接超时。
   - 浏览器提示阻止了弹出式窗口或当前文件下载请求。

### 2.3 排查步骤、结果观察与下一步指引

#### 第一步：查看页面实际错误提示并核对项目内权限等级
- **适用条件**：点击上传后立即报错、上传按钮不可用，或点击下载提示无权限的用户。
- **操作方法**：
  1. 仔细查看页面顶部或上传弹窗中给出的具体错误提示文案。
  2. 查看项目详情页右上角的个人权限标签（或进入 **「项目详情页 > 项目成员与权限」** 查看本人权限等级是 `read`、`comment`、`edit` 还是 `manage`）。
- **观察结果与下一步**：
  - **结果 A：权限标签显示为 `read` 或 `comment`（或当前空间角色为 `guest`）导致无法上传** → 属于权限边界限制。若你是 `member`，请联系该项目负责人（`manage`）或本空间 `admin` 在 **「项目成员与权限」** 页面将你的权限调整为 `edit`；若你是 `guest`，按平台规则不可直接获得 `edit` 权限，可请拥有 `edit`/`manage` 权限的正式成员协助处理。
  - **结果 B：页面弹窗明确提示文件格式不支持、文件名不合法或超出限制** → 请严格按照页面弹出的实际提示文字调整文件格式、重命名文件（去除特殊符号）或调整后再试。
  - **结果 C：页面显示权限为 `edit`/`manage` 且无格式违规提示，但上传进度条卡住或下载无反应** → 继续执行第二步。

#### 第二步：检查本地文件状态并进行小文件对比测试
- **适用条件**：页面显示具备 `edit`/`manage` 权限，但上传特定文件时进度停滞或反复失败。
- **操作方法**：
  1. 在本地电脑上确认待上传文件未被其他程序独占锁定，可正常打开且非 0 字节空文件；尝试将该文件复制到本地桌面并改为简短纯英文/数字文件名。
  2. 新建一个仅含几行文字的普通纯文本小文件，在同一项目文档中尝试上传，对比观察结果。
- **观察结果与下一步**：
  - **结果 A：普通小文件可以上传成功，仅原文件上传失败或停滞** → 说明两次上传测试存在差异，提示问题可能与原文件自身属性（如文件体积、格式、文件名字符或本地读取状态）或较长传输过程中的连接波动有关，尚不能据此直接确认单一根因。请结合页面实际提示文字核查原文件状态；若需对比网络环境，请在符合组织网络规范的前提下进行测试（如涉及个人自行配置的代理，仅在本人有权调整且符合组织规则的条件下做单项对比，测试后恢复原配置）。
  - **结果 B：连极小的测试文件也一直停留在 0% 或立即报失败提示** → 继续执行第三步。

#### 第三步：核查浏览器下载提示与网络传输状态
- **适用条件**：所有文件均无法上传，或点击下载按钮毫无反应。
- **操作方法**：
  1. **针对下载无响应**：先记录页面是否有报错提示，并查看浏览器地址栏或下载栏是否明确提示该次下载被阻止。**仅当浏览器明确提示该下载被阻止、且你已核实当前访问的是协作平台可信域名时**，再根据浏览器实际给出的拦截原因按需处理当次下载，并检查本地磁盘剩余空间是否充足（请勿无条件关闭终端安全防护或随意将未知站点设为长期放行）。
  2. **针对上传停滞与下载中断**：优先打开浏览器开发者工具记录失败请求的状态码，并尝试在浏览器无痕窗口中对比测试；如怀疑网络环境影响，仅在允许的测试网络下进行对比（不要关闭企业受管代理、VPN 或安全扫描）。
- **观察结果与下一步**：
  - **结果 A：在确认可信域名后按浏览器提示处理当次被拦截下载，或在无痕窗口对比测试后恢复正常** → 可进一步排查原窗口的扩展冲突或特定浏览器拦截项。
  - **结果 B：无痕窗口及合规网络对比后，上传/下载依然失败** → 记录页面报错提示与脱敏请求信息，准备提交支持工单。

### 2.4 仍未解决时建议保留的脱敏信息
- 所在工作空间标识（`workspace_id`）、项目标识（`project_id`）及你在该项目中的权限等级（`read` / `comment` / `edit` / `manage`）；
- 操作类型（上传或下载）、文件扩展名类型、大约文件体积及操作发生的时间点；
- 页面弹窗显示的完整错误提示文字（切勿上传含商业机密的原文件或提供明文密钥）。

### 2.5 与现有功能或权限文档的关联

## 3. 文档保存与协同不同步（文档无法保存、只读无法输入、同事看不到最新修改、协同更新延迟）

### 3.1 你可能看到的现象
- 在项目文档中输入文字或修改表格后，页面顶部提示“保存失败”“离线状态，正在重连”，或者快捷键保存后提示无法写入（文档无法保存）。
- 打开文档后光标无法输入任何正文内容，工具栏编辑按钮全部置灰。
- 你在自己电脑上已经修改了文档，但同一项目的另一位成员打开文档时看不到你的最新修改，或者对方看到的内容更新有明显延迟（协同不同步）。

### 3.2 需要区分的条件与尚未核实的可能原因
在排查文档保存失败或多人协同不同步时，**切勿将“刷新页面、退出登录或清理浏览器缓存”作为第一步**，否则可能导致当前尚未同步到服务端的本地修改丢失。请先区分以下四类待核实条件：

1. **当前编辑器中是否存在尚未保存成功的本地内容**：决定了你必须先备份并核对内容，再做任何页面刷新或重登操作。
2. **账号在当前项目中的权限等级是否支持编辑（或编辑中途权限是否发生变更）**：
   - 只有本空间管理员（`admin`）及对该项目拥有 `edit` 或 `manage` 权限的正式成员（`member`）可以编辑文档正文。
   - 若你当前仅拥有 `read`（只读查看）或 `comment`（可批注）权限（或者你在打开文档期间，项目负责人/`admin` 将你的权限从 `edit` 下调为 `read`/`comment`，或将你的空间角色改为了 `guest`），文档将处于只读或仅批注模式，正文修改无法写入服务端。
3. **双方打开的是否为同一工作空间、同一项目下的同一篇实时文档**：
   - 协作者可能误打开了同名但不同工作空间或不同 `project_id` 下的文档、停留在旧的本地离线标签页，或正在查看 **「版本历史」** 中的某个历史快照而非当前实时编辑页。
4. **客户端网络连接、服务响应与实时协同状态**：
   - 修改方或查看方的网络连接异常，或保存请求未获服务端成功响应。

### 3.3 排查步骤、结果观察与下一步指引

#### 第一步：立即备份当前尚未保存的文档内容并检查备份完整性（最高优先级）
- **适用条件**：所有遇到“保存失败”“正在重连”或发现同事看不到你最新输入内容的用户。
- **操作方法**：**在点击浏览器刷新按钮、切换工作空间、退出登录或清理缓存之前**，先在当前文档编辑器中选中你刚刚新增或修改的文字、代码块或表格内容，复制到本地电脑的记事本或备忘录中，并仔细检查备份文本是否完整；由于纯文本复制不一定能完整保留复杂排版格式、附件或批注位置，必要时请同时对当前编辑区域进行脱敏截图，以辅助保留格式与编辑差异。
- **观察结果与下一步**：确认本地已留存核对后的文本备份及必要的脱敏截图后，再继续执行第二步排查。

#### 第二步：核对文档右上角权限状态与编辑器顶部状态提示
- **适用条件**：已完成未保存内容备份，需区分权限限制、明确断网提示或保存请求异常。
- **操作方法**：查看文档页面右上角的权限徽标（及 **「项目详情页 > 项目成员与权限」** 中的实际记录），并查看编辑器顶部的状态提示文字。
- **观察结果与下一步**：
  - **结果 A：右上角显示为「只读（`read`）」或「可批注（`comment`）」** → 说明当前账号无文档正文编辑权（`read` 仅可阅读，`comment` 仅可划词添加批注，`guest` 角色不支持获得 `edit` 权限）。若你是需要编写文档的 `member`，请联系该项目负责人（`manage`）或本空间 `admin` 在 **「项目详情页 > 项目成员与权限」** 中将你的权限设为 `edit`。
  - **结果 B：页面显示权限为「可编辑（`edit`）」或「可管理（`manage`）」，但顶部提示“网络已断开”或“保存失败”** → 需区分两类提示分别处理：
    - **若顶部明确提示“网络已断开/离线状态”**：提示可能与本地网络连接中断有关。请先检查本地网络是否连通（若存在个人自行配置的代理工具，仅在本人有权调整且符合组织规则的条件下进行单项测试，测试后恢复原配置；请勿关闭企业受管代理或 VPN），观察顶部状态栏是否恢复。
    - **若网络正常但顶部仅提示“保存失败”**：保存失败本身可能涉及权限变更、会话状态或服务端响应异常，尚不能直接判定为协同连接中断。
    - **如需刷新页面验证**：必须在确认已完成第一步完整备份的前提下刷新。刷新页面后，**先检查当前文档正文是否已包含部分改动、是否存在其他协作者的新增修改，再与本地备份比对，仅补回确实缺失的部分（切勿直接全选覆盖或无条件重复粘贴）**。**若刷新后文档仍变为只读、权限不足或连接/保存仍未恢复，重新粘贴并不能保证保存成功**，请保留本地备份与脱敏报错提示继续通过工单反馈。
  - **结果 C：你这边顶部显示正常，但同事反馈看不到最新内容** → 继续执行第三步。

#### 第三步：核对协作者双方打开的文档标识、实时视图与「版本历史」辅助记录
- **适用条件**：修改方认为已完成修改，但另一位成员看不到最新内容。
- **操作方法**：
  1. **核对同一工作空间、同一项目与同一篇实时文档**：双方分别查看左上角 **「工作空间切换器」**（确认 `workspace_id` 一致）、当前项目的 `project_id` 以及文档打开路径/链接，并确认双方均处于当前实时正文视图而非 **「版本历史」** 预览界面（注意：**不要仅凭文档标题相同就确认为同一篇文档**，不同项目或空间下可能存在同名文档）。
  2. **结合「版本历史」做辅助参考**：点击文档右上角的 **「版本历史」** 按钮，辅助查看修改记录列表中是否已出现相关记录。
- **观察结果与下一步**：
  - **结果 A：已确认双方处于同一工作空间、同一 `project_id` 的同一篇实时文档（非历史预览视图），且修改方在当前实时正文及「版本历史」中均能看到修改，但查看方同事仍看不到** → 提示查看方同事的页面可能尚未同步最新内容。请查看方同事在确认其自身无未保存内容后刷新浏览器页面，观察是否拉取到最新正文；若刷新后仍不一致，请双方保留脱敏信息反馈。
  - **结果 B：修改方在「版本历史」中未看到刚才的修改记录** → 由于「版本历史」仅作为查看修改记录的辅助参考，未看到某次记录时**尚不能单独据此确认保存结果**。请修改方在确认第一步备份完整的前提下刷新页面，**先检查刷新后的当前文档正文是否已保留刚才的改动，再与本地备份比对：若确实缺失且当前无其他协作者冲突修改，仅补回缺失部分（若存在他人新修改请先沟通协调，切勿直接全选覆盖）**；若补回后仍无法保存或页面处于只读/异常状态，请保留本地备份与脱敏现象提交工单反馈。

### 3.4 仍未解决时建议保留的脱敏信息

### 3.6 常见问题（FAQ）

#### 问：我在文档里写了半天发现提示“保存失败”，能不能让 Ordo 帮我从后台恢复或者直接帮我强制保存？我该马上刷新页面重新粘贴吗？
答：**请不要马上刷新页面、不要退出登录或清理缓存！** Ordo 智能支持中心不连接后台文档存储服务，无法在聊天窗内代你强制保存或恢复未上传的本地内容。请按以下顺序安全处理：
1. **先做完整本地备份**：在当前未关闭的编辑器页面中，将新增或修改的文字、表格复制到本地记事本，检查备份内容是否完整，必要时配合脱敏截图保留排版格式与修改位置。
2. **核对文档归属与权限状态**：确认当前处于正确的工作空间与 `project_id`，且页面右上角权限标签仍为 `edit` 或 `manage`。
3. **谨慎核对后再补回缺失内容**：如需刷新页面，刷新后**先检查当前文档正文是否已有保存内容、是否存在其他协作者的新增改动，再与本地备份比对，仅补回确实缺失的部分（切勿直接全选覆盖或无条件整篇重复粘贴）**，并可查看 **「版本历史」** 作为辅助参考。若刷新后文档仍为只读、权限不足或依然报错无法保存，重新粘贴也无法保证保存成功，请妥善保留本地备份与脱敏报错现象前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面反馈。

## 4. 通知与协作提醒未收到（@提及未收到提醒、批注通知不显示、没有系统弹窗）

### 4.1 你可能看到的现象
- 同事说已经在项目文档的批注或讨论区里 `@` 了你（`@提及`），但你表示没有收到任何提醒。
- 你在文档里添加了划词批注并 `@同事`，对方反馈电脑桌面或浏览器没有任何弹窗提示，不确定批注是否生效。

### 4.2 需要区分的条件与尚未核实的可能原因
协作平台的批注与 `@` 提及提醒遵循明确的权限与站内通道规则（**本平台已定义的通知依据为左侧主导航栏「工作台 > 收到的批注提醒」，未定义浏览器/操作系统桌面弹窗推送，也不提供外部邮件、短信或第三方软件推送承诺**）。排查时需严格区分以下三类待核实条件：

1. **发起方的批注或讨论是否已规范选中协作者并点击「发布」按钮**：
   - 发起方必须对该项目拥有 `comment`、`edit` 或 `manage` 权限（仅拥有 `read` 权限的用户无法发布批注或 `@` 提及）。
   - 在输入框键入 `@` 后，必须从弹出的当前项目协作者候选下拉列表中点击选中目标同事，并在填写内容后点击 **「发布」** 按钮。如果仅手打了纯文本字符、未点击 **「发布」**（例如只停留在输入框草稿状态），系统不会生成任何提醒。
2. **被提及对象的账号身份与项目访问权限是否符合规则**：
   - 被 `@` 提及的同事必须已经是当前项目的有权访问者：对于公开项目（`workspace_public`），本工作空间的 `admin` 和 `member` 默认有访问权；对于私有项目（`private`），普通 `member` 必须已被添加进该项目的 **「项目成员与权限」** 列表（或已通过 `read` 权限申请且状态为 `approved`）；对于访客（`guest`），无论是公开项目还是私有项目，都必须已被明确添加为该项目协作者。
   - 被提及的同事查看提醒时，必须登录正确的账号并切换到该项目所在的工作空间（`workspace`）。
3. **没有桌面弹窗不等于没有平台站内提醒**：
   - **不能把“没有看到浏览器或电脑桌面弹窗”直接等同于“没有收到平台站内提醒”**。本平台已定义的通知依据是站内 **「工作台 > 收到的批注提醒」** 列表，没有桌面弹窗本身不作为站内通知故障的判断依据。

### 4.3 排查步骤、结果观察与下一步指引

#### 第一步：在被提及人的平台页面核对工作空间与「收到的批注提醒」列表
- **适用条件**：被 `@` 的同事反馈“没看到弹窗”或“没收到通知”。
- **操作方法**：
  1. 请被提及的同事查看页面左上角 **「工作空间切换器」**，确认当前所处的工作空间与目标项目所属的工作空间一致。
  2. 点击左侧主导航栏 **「工作台」**，查看 **「收到的批注提醒」** 模块列表。
- **观察结果与下一步**：
  - **结果 A：在「工作台 > 收到的批注提醒」列表中能够看到该条 `@` 提醒，点击即可跳转到对应文档段落** → 说明平台站内提醒已正常送达。本平台以 **「工作台 > 收到的批注提醒」** 作为通知依据，没有浏览器或桌面弹窗不属于站内通知故障，直接通过站内列表查看与跳转即可。
  - **结果 B：确认工作空间无误，但「工作台 > 收到的批注提醒」列表中确实没有任何记录** → 继续执行第二步。

#### 第二步：在发起人的文档页面核对批注是否已成功「发布」及 `@` 选中状态
- **适用条件**：被提及人在站内 **「工作台 > 收到的批注提醒」** 中查无记录。
- **操作方法**：请发起批注的同事打开目标项目文档，查看右侧 **「批注栏」** 或底部 **「讨论与批注」** 页签。
- **观察结果与下一步**：
  - **结果 A：右侧「批注栏」或「讨论与批注」中没有这条留言，或文字仍停留在未提交的输入框内** → 说明发起人刚才尚未完成提交。请发起人输入 `@`、从下拉候选框中点选目标同事姓名，填写意见后明确点击 **「发布」** 按钮，确认该条记录已正式出现在批注栏中。
  - **结果 B：批注已发布，但 `@姓名` 显示为普通纯文本而非选中的协作者标签，或者输入 `@` 时下拉列表里搜不到该同事** → 继续执行第三步，核对被提及人的项目访问条件。
  - **结果 C：批注已点击「发布」出现在批注栏中，且已正确选中目标 `@` 协作者对象，但接收方站内「工作台 > 收到的批注提醒」中仍无记录** → 请勿反复重发相同批注；继续执行第三步，进一步核对接收方实际登录的账号标识（`user_id`）、当前切换的工作空间（`workspace_id`）及项目访问权限状态。

#### 第三步：核对被提及同事的登录账号、工作空间与项目访问条件
- **适用条件**：输入 `@` 时候选列表中找不到该同事，或批注已正确发布但对方站内仍未看到提醒。
- **操作方法**：
  1. 请被提及同事在右上角 **「个人头像 > 账号与身份」** 核对当前登录的 `user_id` 与发起人 `@` 选中的账号是否一致，并确认左上角 **「工作空间切换器」** 处于同一 `workspace_id`。
  2. 进入该项目的 **「项目详情页 > 项目成员与权限」** 页签，检查该同事是否在协作者列表中，同时核对该项目是 `workspace_public`（公开）还是 `private`（私有），以及该同事的空间角色是 `member` 还是 `guest`。
- **观察结果与下一步**：
  - **结果 A：该项目是私有项目（`private`）且该 `member` 不在协作者列表中，或该同事是访客（`guest`）且尚未被添加进该项目** → 因为对方没有该项目的访问权，所以无法作为该项目协作者接收提醒或查看批注。请由该项目负责人（`manage`）或本工作空间 `admin` 在 **「项目成员与权限 > + 添加协作者」** 中将该同事加入项目（授予 `read`、`comment` 或 `edit`，其中 `guest` 最高仅可授予 `comment`），或者让该同事在 **「项目中心 > 申请访问项目」** 提交 `read` 申请并获批后，再在批注中 `@` 对方并点击 **「发布」**。
  - **结果 B：确认批注已发布、选中对象正确，且接收方登录账号、工作空间与项目访问条件均核对无误，但接收方刷新「工作台 > 收到的批注提醒」仍无记录** → 请勿反复重发相同批注，记录以下脱敏信息并通过 **「帮助与支持 > 我的工单 > + 提交工单」** 页面反馈。

### 4.6 常见问题（FAQ）

#### 问：我在文档批注里 `@` 了外部顾问（`guest`），为什么输入 `@` 时列表里没有他？另外为什么电脑桌面没有弹窗、也没有收到邮件或手机短信通知？
答：请从以下两方面核对：
1. **为什么 `@` 候选列表里没有该外部顾问**：访客（`guest`）仅能访问明确授权给自己的项目（即使该项目是团队公开项目 `workspace_public` 也不默认可见）。如果还没有把这位 `guest` 添加到当前项目的协作者列表中，他在该项目内就没有访问权限，因此不会出现在当前项目的 `@` 候选列表里。请项目负责人或本空间 `admin` 先进入 **「项目详情页 > 项目成员与权限 > + 添加协作者」** 将该 `guest` 加入项目（可授予 `read` 或 `comment`，`guest` 最高权限为 `comment`），随后即可在批注中 `@` 他并点击 **「发布」**。
2. **关于通知渠道说明**：本平台已定义的批注与 `@` 提及通知依据为站内左侧导航栏 **「工作台 > 收到的批注提醒」** 列表，未定义桌面弹窗推送、外部邮件或手机短信下发；没有桌面弹窗不代表通知异常，请引导协作者登录平台后直接前往 **「工作台 > 收到的批注提醒」** 查看。

## 5. 附：如何区分网页端技术故障与固定产品 API 调用报错？

如果你在使用外部脚本或 **「开发者与 API 中心 > 沙箱调试台」** 调用固定产品接口（`GET /sandbox/product/v1/me`、`GET /sandbox/product/v1/projects`、`GET /sandbox/product/v1/projects/{id}`）时遇到报错，请注意将 API 报错与网页端故障区分开来，并遵守以下安全排查原则：

1. **网页能打开项目，但调用 API 仍返回 HTTP `403`**：
   - API 的接口权限范围（`project:read`）与调用用户的项目访问权是两个独立条件。即使你在网页端有权限查看该项目（包括工作空间 `admin` 默认拥有本空间全部公开和私有项目的资源访问权），只要你调用 API 所使用的凭据（`credential`）未勾选 `project:read`，接口仍会返回 `403 INSUFFICIENT_SCOPE`。请前往 **「开发者与 API 中心 > 凭据管理」** 检查并勾选 `project:read`。
2. **排查技术故障与 API 报错时的安全禁令**：
   - **严禁借用或更换为管理员（`admin`）的凭据代测**：修复问题后必须使用原调用用户身份及对应凭据复测。
   - **严禁为了绕过权限报错而擅自将涉密私有项目（`private`）改为团队公开（`workspace_public`）**。
   - **严禁在对话窗或工单中粘贴完整的明文密钥（`credential_token`）或账号密码**。
3. **关联 API 与工单文档**：
   - 固定接口的参数、请求头与沙箱调试方法，请参考《05_API接入指南与接口说明.md》的“2. 调用固定产品 API 时，认证方式、请求头与四重校验规则是什么？”与“6. 如何使用平台「沙箱调试台」进行测试与原身份复测？”。
   - 针对 `400`、`401`、`403`（三种缺权场景）与 `429`（`RATE_LIMITED` 单凭据 60 次/60 秒、`QUOTA_EXCEEDED` 工作空间 5,000 次/自然日）的详细排错步骤，请参考《06_API错误排查手册.md》。
   - 当按本文档完成全部检查后问题仍未解决，需要整理反馈材料并前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面提交工单时，请参考《07_权限申请人工支持与工单流程.md》的“4. 如何整理问题反馈材料并在页面提交支持工单？”。
