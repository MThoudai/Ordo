# 协作平台与 Ordo 智能支持中心概述及支持范围

## 1. 协作平台与 Ordo 智能支持中心分别是什么关系？

**协作平台**是面向企业团队的在线项目管理与文档协同 SaaS 系统，提供工作空间管理、项目创建与可见性控制、项目文档协同编辑与批注、团队成员邀请与角色分配，以及固定产品 API 接入能力。

**Ordo 智能支持中心**（简称 **Ordo**）是内嵌在协作平台中的智能支持助手（位于平台右上角 **「帮助与支持 > Ordo 智能支持中心」**）。当你在协作平台中遇到功能操作疑问、项目访问受阻或 API 报错时，可以通过以下两种方式配合解决：

- **直接在协作平台页面完成操作**：按照知识库提供的菜单路径、按钮与步骤，在 **「项目中心」**、**「空间管理后台」**、**「开发者与 API 中心」**、**「帮助与支持 > 我的申请」** 或 **「帮助与支持 > 我的工单」** 页面自助完成查询、配置与提交。
- **通过 Ordo 智能支持中心检索指南与分析问题**：在 Ordo 对话窗描述问题或粘贴脱敏报错信息，由助手检索知识库资料、解释平台权限与接口规则、指导你在对应平台页面自助操作，或根据你提供的信息做条件分析、协助整理可复制的权限申请理由与问题反馈材料。

> **重要区分说明**：知识库文档与 Ordo 的回答用于介绍协作平台的通用功能规则与标准页面操作步骤。**Ordo 不连接实时业务系统，不能直接读取你当前登录账号的真实角色、项目授权、配置进度、API 调用日志、配额余量、申请状态或工单进度，也不能在聊天窗内代为执行操作、运行沙箱测试、创建确认卡片或直接提交申请与工单**。如需核实本人真实状态或办理业务，请前往协作平台对应页面查看与操作，并以页面实际记录为准。

## 2. 租户、工作空间、成员、项目、文档与 API 凭据之间是什么关系？

协作平台采用严格的多层级对象模型与租户隔离机制。理解各核心对象之间的归属关系，是日常管理项目、分配权限与调用 API 的基础：

| 核心对象 | 英文标识 | 在协作平台中的定位与作用 | 与上下游对象的归属及隔离关系 |
| :--- | :--- | :--- | :--- |
| **企业租户** | `tenant` | 企业级数据安全隔离的最高边界 | 不同企业租户之间的数据、成员、项目、文档、API 凭据与工单完全隔离，严禁任何跨租户访问 |
| **工作空间** | `workspace` | 企业租户内的团队协作空间 | 归属于唯一企业租户，承载团队成员名录、空间安全设置与全部项目 |
| **空间成员身份** | `membership` | 用户在当前工作空间内的角色身份 | 绑定具体用户与工作空间，角色分为管理员（`admin`）、正式成员（`member`）和访客（`guest`） |
| **项目** | `project` | 工作空间下的业务协作单元 | 归属于特定工作空间，可见性分为团队公开项目（`workspace_public`）和私有项目（`private`） |
| **项目文档与讨论** | `document` | 项目内的在线协同文档、批注与讨论区 | 隶属于具体项目，遵循所在项目的访问范围及成员在项目内的权限等级（`read` / `comment` / `edit` / `manage`） |
| **API 凭据** | `credential` | 调用平台固定 API 的认证令牌 | 绑定所属租户、工作空间、调用用户本人、接口权限范围（`scope`）及有效期，平台仅保存哈希值与脱敏标识 |

在协作平台中，以下三条核心业务规则贯穿所有功能模块：

1. **三种工作空间角色的默认边界不同**：
   - **管理员（`admin`）**：管理本工作空间的全部公开项目（`workspace_public`）与私有项目（`private`）及相关文档，可跨部门接管项目、调整项目可见范围、管理成员邀请与角色分配、审批本空间内所有项目的访问申请、查看审计日志。
   - **正式成员（`member`）**：默认可访问本工作空间的公开项目（`workspace_public`），访问私有项目（`private`）需获得该项目授权；可创建项目与文档，在授权范围内协同编辑、批注和分享。
   - **访客（`guest`）**：仅可访问明确授权给自己的项目（公开项目也不默认可见），按授权仅可查看（`read`）或添加批注（`comment`），最高权限不超过 `comment`，不可编辑项目主体内容或扩大共享范围。
2. **工作空间身份与 API 调用条件独立校验**：即使调用用户本人有权访问某项目（例如 `admin` 默认拥有本空间全部项目的资源访问权），通过 API 读取该项目时，所使用的 API 凭据仍必须包含对应的接口权限范围（`project:read`）且配额充足，缺一不可。
3. **跨租户访问一律阻断**：任何角色（包括 `admin`）均无法查看、接管、申请或通过 API 调用其他企业租户（`tenant`）下的任何资源。

## 3. Ordo 智能支持中心可以处理哪些问题？

当你在协作平台右上角打开 **「帮助与支持 > Ordo 智能支持中心」** 时，助手可围绕以下四个支持域为你提供知识解答、页面操作指引与条件分析：

### 3.1 功能上手与页面操作指导
- 解答如何进入和切换工作空间、创建公开或私有项目、查找与管理已有项目、创建与协同编辑项目文档、使用划词批注、`@` 提及同事与讨论区。
- 指导工作空间管理员（`admin`）如何在页面上邀请成员、处理未接受或已失效邀请、修改成员角色、跨部门接管项目与查看安全审计日志。
- 提供新用户上手检查清单，并根据你在对话中说明的当前已完成步骤，给出下一步页面操作建议（助手不直接读取你的后台配置进度）。

### 3.2 成员角色与项目权限规则解释及排查指导
- 解释 `admin`、`member`、`guest` 三种空间角色及 `read`、`comment`、`edit`、`manage` 四级项目权限的具体边界。
- 根据你提供的自身角色与目标项目属性，帮助你分析“为什么在列表里看不到某项目”或“为什么打不开同事分享的项目链接”。
- 指导 `member` 或 `guest` 前往 **「项目中心 > 申请访问项目」** 页面发起项目只读访问（`read`）申请、协助整理申请理由文本，并解释审批分工（由**本工作空间管理员 `admin` 或该项目负责人 `manage`** 审批，项目负责人仅审批自己管理的项目）以及申请状态（`submitted` / `approved` / `rejected`）的含义（助手不直接查询或提交你的申请记录）。

### 3.3 固定产品 API 规范解释与报错分析
- 解释三个固定产品接口（`GET /sandbox/product/v1/me`、`GET /sandbox/product/v1/projects`、`GET /sandbox/product/v1/projects/{id}`）的用途、认证请求头、所需 `scope`（`profile:read`、`project:read`）、参数约束及响应格式。
- 根据你提供的 HTTP 状态码或脱敏错误响应（如 `error.code` 与 `error.details`），为你分析 `400`、`401`、`403`（区分缺 `scope`、缺项目权限或两者皆缺）、`429`（区分 `RATE_LIMITED` 与 `QUOTA_EXCEEDED`）的触发原因。
- 指导你前往 **「开发者与 API 中心 > 凭据管理」**、**「调用记录与配额看板」** 及 **「沙箱调试台」** 页面自行核查凭据、执行沙箱测试与原身份复测（助手不在对话窗内代为运行 API 或读取后台调用日志）。

### 3.4 问题反馈材料整理与工单流程说明
- 当你按文档步骤排查后问题仍未解决，或遇到工作空间日累计调用配额耗尽（`QUOTA_EXCEEDED`）等情况时，指导你如何区分“提交项目权限申请”与“提交问题反馈工单”。
- 根据你在对话中提供的故障现象、涉及对象、脱敏错误码与已尝试步骤，协助你整理结构化的**可复制问题反馈材料**，供你前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面自行粘贴提交。
- 解释平台工单状态（`open` → `in_progress` → `waiting_user` / `resolved` → `closed`）的流转含义与页面查看方法（助手不直接创建工单、不返回真实工单号，也不读取你名下的实时工单进展）。

## 4. 哪些事项不在当前平台与支持中心的服务范围内？

为了让你快速判断问题归属，以下事项不在当前项目管理场景与 Ordo 智能支持中心的支持范围内：

- **商务、计费与合同**：不涉及套餐订阅升级、费用账单查询、发票开具或商务合同签署。
- **外部身份与生产密钥托管**：不支持企业单点登录（SSO/SAML/OIDC）配置、外部组织架构自动同步或生产环境 KMS 密钥托管。
- **扩展开发组件**：不提供多语言复杂 SDK 下载、Webhook 事件回调订阅，平台沙箱调试台不支持请求任意外部 URL 或执行自定义代码脚本。
- **实时人工客服坐席与后台代操作**：**平台当前暂未接入实时在线人工客服系统，且 Ordo 助手不执行后台写操作**。用户在 **「帮助与支持 > 我的工单」** 页面提交工单仅代表将问题登记至平台工单列表以供异步排查，**不承诺已接通实时人工客服、不承诺外部工单系统已受理，也不提供固定人工响应时限（SLA）承诺**。

## 5. 示例：如何结合平台页面与 Ordo 解决团队协作问题？

> **示例说明（以下为假设情境，仅供演示页面操作与助手配合方式，非当前用户真实状态）**：  
> **前提设定**：假设在租户“星海科技（`tenant_xh`）”的工作空间中，产品经理小陈（角色为 `member`）刚创建了私有项目“2026 核心改版（`proj_revamp_26`）”，希望邀请研发同事小林（`member`）和外部设计顾问周老师（`guest`）协作，同时用脚本通过 API 拉取该项目信息。

1. **在协作平台页面完成项目创建与成员授权**：
   - 小陈在左侧导航栏点击 **「项目中心 > + 新建项目」**，创建可见性为“私有项目（`private`）”的 `proj_revamp_26`，并在 **「项目文档」** 页签新建《需求规格说明书》。
   - 小陈进入该项目的 **「项目成员与权限」** 页签，点击 **「+ 添加协作者」**，将同空间的研发同事小林添加为 **「可编辑（`edit`）」**，将外部顾问周老师添加为 **「可批注（`comment`）」**。
2. **未获授权成员咨询 Ordo 并在页面提交权限申请**：
   - 测试工程师小王（`member`）收到小陈在群里发的项目链接后打不开。小王打开右上角 **「Ordo 智能支持中心」**，告知助手：“我是空间 `member`，点开同事发的私有项目 `proj_revamp_26` 提示无权限，该怎么办？”
   - Ordo 根据小王提供的信息解释规则：`member` 默认仅可见公开项目，访问私有项目需先获授权；并指导小王在无权限提示页或 **「项目中心 > 申请访问项目」** 页面填写 `proj_revamp_26` 提交只读访问（`read`）申请。
   - 小王按指引在页面提交申请后（状态为 `submitted`），由该项目负责人小陈在项目的 **「项目成员与权限 > 待审批申请」** 页签（或由本工作空间管理员张总监在 **「空间管理 > 权限审批中心」**）点击 **「批准」**（状态变为 `approved`），小王刷新页面即可只读浏览该项目。
3. **根据脱敏报错分析 API 403 并在页面完成修复复测**：
   - 小陈用自己的 API 凭据 `cred_chen_01` 调用 `GET /sandbox/product/v1/projects/proj_revamp_26` 返回 `403`，响应中包含 `"code": "INSUFFICIENT_SCOPE"`。小陈将该脱敏报错粘贴到 Ordo 询问原因。
   - Ordo 分析指出：虽然小陈是项目创建者（满足用户资源访问权），但错误码 `INSUFFICIENT_SCOPE` 表明凭据 `cred_chen_01` 缺少 `project:read` 权限范围（`scope`）。
   - 小陈按指引前往 **「开发者与 API 中心 > 凭据管理」** 为 `cred_chen_01` 勾选 `project:read` 并保存，随后在 **「API 中心 > 沙箱调试台」** 页面选用原凭据重新测试并观察到返回成功。

## 6. 常见问题（FAQ）

### 问：知识库文档写着“正式成员（member）可以访问公开项目”，或者我在 Ordo 里问了权限规则，这能证明我现在就能打开某个具体项目吗？
答：不能直接证明。知识库文档与 Ordo 的回答仅解释协作平台的通用权限规则，Ordo 不会实时读取你当前账号的后台权限数据。你当前实际能否打开某个项目，需由你在平台页面自行核实：（1）在左上角 **「工作空间切换器」** 或右上角 **「个人头像 > 账号与身份」** 核对你在目标工作空间中的真实角色是 `admin`、`member` 还是 `guest`；（2）在 **「项目中心」** 查看目标项目是否可见，或确认该项目属于本企业租户且你已获得对应授权。

### 问：我在 Ordo 智能支持中心咨询了问题并让助手帮我整理了反馈材料，是不是说明已经提交了工单、马上会有人工客服在聊天框回复我？
答：不是。首先，Ordo 智能支持中心不会在聊天窗内直接替你创建工单，助手为你整理的反馈材料只是供你复制的文本草稿；你需要自行前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面填写并点击提交，生成状态为 `open` 的工单记录。其次，协作平台当前暂未接入实时在线人工客服坐席，提交工单后不会有人工坐席在聊天框实时接入，请通过 **「帮助与支持 > 我的工单」** 页面查看后续公开事件更新，平台不承诺固定的人工响应时限。
