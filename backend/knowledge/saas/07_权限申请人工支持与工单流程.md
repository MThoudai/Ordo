# 权限申请、问题反馈与支持工单流程

## 1. 遇到问题时，我应该发起项目权限申请、找管理方调整权限，还是提交支持工单？

当你在协作平台中遇到项目无法访问、文档无法批注/编辑或 API 持续报错时，请先根据下表判断正确的页面处理通道。请注意：**所有权限申请、权限调整与工单提交均需在协作平台对应页面操作完成，Ordo 智能支持中心仅负责解答规则、指导页面步骤及协助整理可复制的文字材料，不会在聊天窗内代为执行或直接提交。**

| 你遇到的具体场景 | 应选择的处理方式 | 审批 / 处理职责方 | 平台页面入口与后续验证方式 |
| :--- | :--- | :--- | :--- |
| 你是 `member` 需要查看本空间的私有项目（`private`），或你是 `guest` 需要查看本空间的特定项目 | **在页面发起项目 `read` 权限申请** | **本空间管理员（`admin`）或该项目负责人（`manage`）**（负责人仅审批本人管理的项目） | 在 **「项目中心 > 申请访问项目」** 页面提交申请，在 **「帮助与支持 > 我的申请」** 查看状态；变为 `approved` 后刷新页面访问 |
| 调用 `GET /sandbox/product/v1/projects/{id}` 返回 `403 PROJECT_ACCESS_DENIED`（同空间项目缺权） | **在页面发起项目 `read` 权限申请** | **本空间管理员（`admin`）或该项目负责人（`manage`）** | 待页面申请状态变为 `approved` 后，确保凭据已含 `project:read` 且配额充足，使用**原调用身份与原凭据**在 **「沙箱调试台」** 页面复测并观察结果 |
| **你是正式成员（`member`）**，已拥有项目的 `read` 权限，但需要升级为 **可批注（`comment`）** 或 **可编辑（`edit`）** | **联系该项目负责人或本空间 `admin` 在项目内调整** | 该项目负责人（`manage`）或本空间管理员（`admin`） | 由管理方在 **「项目详情页 > 项目成员与权限」** 页面将你的项目权限修改为 `comment` 或 `edit`（在线申请单仅支持申请 `read`） |
| **你是访客（`guest`）**，已拥有项目的 `read` 权限，但需要升级为 **可批注（`comment`）** | **联系该项目负责人或本空间 `admin` 在项目内调整（最高仅限 `comment`）** | 该项目负责人（`manage`）或本空间管理员（`admin`） | 由管理方在 **「项目详情页 > 项目成员与权限」** 页面将你的权限修改为 `comment`；**`guest` 严禁直接授予 `edit` 或 `manage`**（若确需赋予编辑权，须先由本空间 `admin` 评估并在 **「空间管理 > 成员与邀请」** 将空间角色变更为 `member`，助手无法代为修改） |
| 已按《06 API 错误排查手册》核对参数、凭据 `scope` 与项目权限，但页面功能或接口依然异常 | **在页面提交问题反馈与支持工单** | 平台后台技术支持人员（异步排查） | 可先由 Ordo 协助整理反馈材料文本，再前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面提交，并在 **「我的工单」** 页面跟踪状态 |
| API 返回 `429 QUOTA_EXCEEDED`（工作空间单日 5,000 次累计额度耗尽），无法等待次日 `00:00（UTC+8）` 重置 | **在页面提交问题反馈与支持工单** | 平台后台技术支持人员（异步排查） | 整理 `request_id` 与配额看板信息后，前往 **「帮助与支持 > 我的工单 > + 提交工单」** 页面提交（注：提交工单不承诺配额立即恢复） |

## 2. 提交前如何核对信息？如何区分 Ordo 对话草稿与平台正式记录？

在使用 **Ordo 智能支持中心** 辅助排查问题并准备提交权限申请或支持工单时，必须严格区分**“对话窗内的文本草稿”**与**“协作平台页面上的正式记录”**：

### 2.1 对话窗内的文本草稿不等于已提交的平台记录
- **Ordo 不在聊天中直接写入申请或工单**：当前 Ordo 智能支持中心仅提供知识解答、规则分析与文本整理服务，**不会在聊天窗口内创建真实写入后台的确认卡片，不会替你直接提交项目权限申请或支持工单，也不会返回真实的申请单号或工单编号**。
- **整理的材料仅作复制参考**：当你在对话窗请求助手“帮我写一段权限申请理由”或“帮我整理一份 API 报错工单材料”时，助手输出的摘要只是**供你复制使用的文本草稿**。如果你没有亲自前往协作平台对应页面粘贴并点击提交按钮，系统中不会产生任何申请单或工单记录。

### 2.2 在协作平台页面正式提交前的四项核对清单
为避免因填写错误或重复提交导致处理延误，前往平台页面点击提交前，请先核对以下四项信息：

1. **核对当前工作空间与角色身份**：在页面左上角 **「工作空间切换器」** 与右上角 **「个人头像 > 账号与身份」** 中，确认当前登录账号、所属企业租户（`tenant_id`）及工作空间（`workspace_id`）无误。
2. **核对目标对象标识格式**：
   - 若申请项目权限，确认目标 `project_id` 格式符合 `^proj_[a-z0-9_]{3,27}$`（以 `proj_` 开头的小写字母、数字或下划线组合，长度 8～32 位），且属于当前工作空间。
   - 若反馈 API 问题，确认已从响应报文或 **「开发者与 API 中心 > 调用记录与配额看板」** 复制准确的 `request_id`、HTTP 状态码与 `error.code`（请勿在工单正文中粘贴明文 `credential_token`）。
3. **先在页面列表排查是否已有未结记录（防重复提交）**：
   - 提交项目权限申请前，先打开顶部导航栏 **「帮助与支持 > 我的申请」**，检查是否已存在针对同一 `project_id` 且处于 `submitted`（待审批）状态的申请记录。
   - 提交支持工单前，先打开顶部导航栏 **「帮助与支持 > 我的工单」**，检查是否已存在针对同一问题且处于 `open`、`in_progress` 或 `waiting_user` 状态的未关闭工单；若已存在，请直接在该工单详情页补充说明，无需重复新建工单。
4. **以平台页面返回的记录状态为准**：在页面点击提交按钮后，请刷新 **「帮助与支持 > 我的申请」** 或 **「帮助与支持 > 我的工单」** 列表，确认列表中已展示对应的新增记录及状态标识。

## 3. 如何在平台页面发起项目访问申请并理解审批状态？

### 3.1 页面发起申请与查看进度的操作步骤
- **适用角色**：对本工作空间内目标项目尚未获得访问权的 `member` 或 `guest`（`admin` 默认拥有本空间全部公开与私有项目访问权，无需发起申请）。
- **申请权限范围限制**：页面在线申请通道固定用于申请目标项目的 **只读查看权限（`read`）**，不支持在线申请将工作空间角色提升为 `admin`，也不支持将 `guest` 申请为 `edit` / `manage`。
- **操作步骤**：
  1. 点击左侧导航栏 **「项目中心」** 右上角的 **「申请访问项目」** 按钮（或点击他人分享的项目链接，在无权限提示页点击 **「申请只读访问（`read`）」**）。
  2. 在申请弹窗中输入目标项目的 `project_id`（如 `proj_core_01`），填写申请理由（可粘贴你在 Ordo 辅助下整理好的申请说明），点击 **「提交申请」**。
  3. 提交后，点击顶部导航栏 **「帮助与支持 > 我的申请」** 查看本人名下的申请记录与当前状态。
- **审批职责方说明**：
  - 提交后的申请单可由 **本工作空间管理员（`admin`）** 在 **「空间管理 > 权限审批中心」** 审批，或由 **该项目负责人（`manage`）** 在该项目的 **「项目详情页 > 项目成员与权限 > 待审批申请」** 页签中审批（注：项目负责人仅能审批自己负责的项目，不能审批其他项目）。

### 3.2 权限申请的三种状态（`submitted` / `approved` / `rejected`）

> **注意**：下表为协作平台权限申请状态的通用规则解释，**不代表你当前账号的实际申请状态**；本人真实状态请前往 **「帮助与支持 > 我的申请」** 页面查看。

| 申请记录状态 | 状态中文名 | 此时网页端能否打开项目？ | 含义与下一步操作指引 |
| :--- | :--- | :--- | :--- |
| **`submitted`** | 已提交待审批 | **不能**（申请已提交不等于授权已生效） | 申请记录已保存在平台待审队列中，请等待本工作空间 `admin` 或该项目负责人（`manage`）审核 |
| **`approved`** | 已批准并生效 | **能**（系统已自动写入该项目 `read` 只读授权） | 刷新 **「项目中心」** 即可只读浏览该项目与文档；若此前因缺项目权限导致 API 报 `403`，在确认凭据有效、已含 `project:read` 且配额充足后，使用**原调用身份与原凭据**在 **「沙箱调试台」** 复测并观察结果 |
| **`rejected`** | 已拒绝 | **不能** | 审批人未批准本次申请，可在 **「我的申请」** 页面查看拒绝说明；若确因业务分工需要访问，请与该项目负责人或本空间 `admin` 沟通核实 |

## 4. 如何整理问题反馈材料并在页面提交支持工单？

### 4.1 提交支持工单前需要准备的四项材料
当你按照知识库完成页面自查后问题仍未解决，可前往顶部导航栏 **「帮助与支持 > 我的工单 > + 提交工单」** 页面创建工单。你可以先将脱敏信息发给 **Ordo 智能支持中心**，请助手帮你整理包含以下四要素的**可复制反馈材料**（再次提醒：**助手整理出的反馈材料只是文本，不是已创建的工单**）：

1. **具体问题与涉及对象**：说明出现问题的工作空间标识（`workspace_id`）、项目标识（`project_id`）或固定 API 路径（如 `GET /sandbox/product/v1/projects/{id}`）。
2. **业务影响范围**：说明该问题仅影响单个账号查看，还是影响了团队协作进度或定时数据同步。
3. **脱敏诊断证据（Evidence）**：包含从响应报文或 **「调用记录与配额看板」** 获取的 `request_id`、HTTP 状态码、业务错误码（如 `429 QUOTA_EXCEEDED`）及页面提示截图说明（切勿附带明文密钥）。
4. **已尝试的排查步骤与未解决项**：列出你已经按照手册在页面执行过的检查动作（例如“已在凭据管理页面确认勾选 `project:read`，且在我的申请页面确认项目权限已变为 `approved`，但在沙箱调试台使用原凭据复测仍返回错误”）。

### 4.2 平台工单五态流转说明与查看路径
在 **「帮助与支持 > 我的工单 > + 提交工单」** 页面填写上述材料并点击提交后，你可在 **「帮助与支持 > 我的工单」** 列表中查看工单状态与公开事件记录（`ticket_events`）：

> **重要声明**：以下状态定义为协作平台工单模块的通用规则说明，**不代表你当前账号已存在工单或处于某种状态，也不表示本次与 Ordo 聊天已经创建了记录或接通了人工客服**。协作平台当前暂未接入实时人工坐席，**不承诺后台已接单、不承诺优先处理，也不承诺固定的人工响应或解决时限（SLA）**。

| 工单状态值 | 状态中文名 | 状态真实含义 | 用户侧应执行的操作 |
| :--- | :--- | :--- | :--- |
| **`open`** | 已创建待处理 | 用户已在 **「我的工单」** 页面完成提交，记录已写入平台工单列表，等待后台异步查看 | **注意：“工单已提交（`open`）”不等于问题已解决，也不代表已接通人工或后台已受理**；请保留现场配置并关注后续工单详情页更新 |
| **`in_progress`** | 处理排查中 | 后台支持人员正在根据工单中提交的脱敏证据与日志排查原因 | 可在 **「帮助与支持 > 我的工单 > 工单详情」** 页面查看公开事件记录 |
| **`waiting_user`** | 等待用户补充/确认 | 需要你在工单详情页补充复现信息，或请你使用原身份在页面/沙箱复测确认 | 查看 **「工单详情」** 中的公开留言提示，补充信息或使用原账号/原凭据复测后在页面回复结果 |
| **`resolved`** | 问题已解决 | 后台支持人员已更新处理说明并标记为解决 | 按照 **「工单详情」** 中的处理说明，在协作平台页面或 **「沙箱调试台」** 验证问题是否已消除 |
| **`closed`** | 工单已关闭 | 问题确认解决或无需继续处理，工单记录归档 | 流程结束；历史记录仍可在本人 **「帮助与支持 > 我的工单」** 页面查阅 |

## 5. 示例：利用 Ordo 整理材料并在平台页面完成申请与工单提交

> **示例说明（以下为假设情境，仅供演示如何结合助手建议在平台页面完成操作，非当前用户真实状态）**：  
> **前提设定**：假设在“远航物流（`ws_yh_01`）”工作空间中，研发工程师小周（`member`）同时遇到两个问题：（1）需要查看私有项目 `proj_route_26` 的接口文档并留批注；（2）调用 `GET /sandbox/product/v1/projects` 时收到 `429 QUOTA_EXCEEDED`。

1. **事项一：在页面提交项目 `read` 申请并联系项目负责人升级 `comment` 权限**：
   - 小周先在 **Ordo 智能支持中心** 询问：“我是 `member`，看不到私有项目 `proj_route_26`，而且打开后还想在文档里留批注，怎么操作？”
   - Ordo 解释规则并提供指导：在线申请仅支持申请只读查看（`read`）权限，且助手不能代为提交；建议小周先去 **「项目中心 > 申请访问项目」** 页面提交 `read` 申请，获批后再联系该项目负责人或本空间 `admin` 将权限升级为 `comment`。
   - 小周前往 **「项目中心 > 申请访问项目」** 页面填写 `proj_route_26` 并点击 **「提交申请」**，在 **「帮助与支持 > 我的申请」** 中看到状态变为 `submitted`。随后该项目负责人（`manage`）在项目的 **「项目成员与权限 > 待审批申请」** 中点击 **「批准」**（状态变为 `approved`），并在协作者列表中将小周的权限从 `read` 调整为 `comment`，小周即可正常浏览文档并发布批注。
2. **事项二：使用助手整理反馈材料，并自行在「我的工单」页面提交**：
   - 小周将 `GET /sandbox/product/v1/projects` 返回的 `429 QUOTA_EXCEEDED` 脱敏报文发给 Ordo。助手分析指出这是工作空间当日 5,000 次累计调用配额已耗尽（次日 `00:00 UTC+8` 自动重置），并根据小周提供的 `request_id` 与已排查步骤，在对话窗生成了一段结构化的《问题反馈材料草稿》。
   - 小周清楚对话窗中的草稿并不等于已创建工单，于是复制该段文字，自行前往顶部导航栏 **「帮助与支持 > 我的工单 > + 提交工单」** 页面，先确认列表中无重复未结工单后粘贴提交。提交后页面生成一条状态为 `open` 的工单记录，小周后续通过 **「我的工单」** 页面异步查看处理进展。

## 6. 常见问题（FAQ）

### 问：Ordo 在聊天框里帮我整理好了“申请理由”或“问题反馈材料摘要”，是不是说明我的权限申请或工单已经提交成功了？
答：不是。Ordo 智能支持中心不连接后台业务数据库，也不会代你执行提交操作。聊天框中输出的申请理由或问题反馈摘要只是**供你复制使用的文本草稿**，此时系统中并没有产生任何申请单或工单记录。你必须亲自复制这些内容，前往协作平台的 **「项目中心 > 申请访问项目」** 页面（提交权限申请）或 **「帮助与支持 > 我的工单 > + 提交工单」** 页面（提交支持工单）完成表单提交，并在 **「我的申请」** 或 **「我的工单」** 页面列表中看到对应记录，才算真正提交成功。

### 问：为什么我在「我的申请」页面看到权限申请状态已经是 `submitted`，但我去打开项目还是提示没有权限？
答：因为 `submitted` 仅代表你的申请已经保存在平台待审列表中，**申请已提交不等于授权已生效**。只有当**本工作空间管理员（`admin`，在「空间管理 > 权限审批中心」操作）或该项目负责人（`manage`，在该项目「项目成员与权限 > 待审批申请」中操作）**点击 **「批准」**，使申请状态变为 **`approved`** 后，系统才会将你加入项目协作者名单，你才能访问该项目。
