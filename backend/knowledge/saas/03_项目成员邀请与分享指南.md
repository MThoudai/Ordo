# 项目管理、成员邀请、文档协作与分享指南

## 1. 如何邀请新成员加入工作空间并分配角色？

- **适用角色**：仅工作空间管理员（`admin`）可邀请成员加入工作空间并分配初始角色；正式成员（`member`）和访客（`guest`）无权邀请空间成员。
- **前提条件**：已使用 `admin` 账号登录目标工作空间，并获取受邀人的企业登录邮箱或账号标识。
- **页面路径与按钮**：左侧导航栏 **「空间管理 > 成员与邀请」** → 右上角 **「+ 邀请成员」** 按钮。
- **操作步骤**：
  1. 在左侧导航栏点击 **「空间管理 > 成员与邀请」**，默认进入 **「正式与访客成员列表」** 页签。
  2. 点击页面右上角的 **「+ 邀请成员」** 按钮，在弹窗中填写受邀人信息：
     - **受邀人账号/邮箱**（必填）：输入一个或多个受邀人的登录邮箱（确保不属于其他冲突租户）。
     - **分配空间角色**（必填）：
       - 选择 **「正式成员（`member`）」**：加入后默认可访问本空间全部公开项目（`workspace_public`），并可创建项目与文档。
       - 选择 **「访客（`guest`）」**：加入后仅能访问明确授权给本人的项目（公开项目也不默认可见），仅可按授权查看或批注。
       - 选择 **「管理员（`admin`）」**：加入后拥有本空间全部公开与私有项目、成员及安全设置的完整管理权限。
     - **初始项目授权（可选）**：可在邀请时直接勾选需要同步授权给该成员的特定项目及项目权限等级（如为 `guest` 预先勾选某项目并授予 `read` 或 `comment` 权限）。
  3. 点击 **「生成并发送邀请」**，系统会创建一条有效期为 **7 天** 的空间邀请记录，同时提供可复制的专属邀请链接。
- **预期结果**：邀请记录写入 **「邀请记录与状态」** 页签（初始状态为 `pending` 待接受）；受邀人点击邀请链接并完成登录确认后，状态变为 `accepted`（已加入），正式获得对应空间角色。
- **失败时的处理方法**：
  - **提示“该账号已存在于当前工作空间”**：可在 **「正式与访客成员列表」** 搜索该账号；若对方已在列表中但角色不符，直接点击该成员右侧的 **「修改角色」** 即可，无需重复邀请。

## 2. 如何查看邀请状态、处理未接受或已失效的邀请？

- **适用角色**：仅工作空间管理员（`admin`）。
- **前提条件**：已发起过工作空间成员邀请。
- **页面路径与按钮**：左侧导航栏 **「空间管理 > 成员与邀请」** → 顶部 **「邀请记录与状态」** 页签。
- **操作步骤**：
  1. 进入 **「空间管理 > 成员与邀请」**，点击顶部切换至 **「邀请记录与状态」** 页签。
  2. 查看每条邀请记录的当前状态标识：
     - **`pending`（待接受）**：邀请仍在 7 天有效期内，受邀人尚未完成点击确认。管理员可点击右侧 **「复制邀请链接」** 直接通过即时通讯工具发给受邀人，或点击 **「撤回邀请」**（状态变为 `revoked`）立即中止该邀请。
     - **`expired`（已失效）**：超过 7 天未接受，原邀请链接已自动作废。管理员可点击右侧 **「重新生成邀请」** 按钮刷新有效期并获取新链接。
     - **`accepted`（已加入）**：受邀人已成功加入工作空间，记录归档备查。
- **预期结果**：清晰掌握受邀人是否已完成空间准入，及时清理误发邀请或激活过期邀请。
- **失败时的处理方法**：
  - **受邀人点击邀请链接提示“邀请已失效或已被撤回”**：请管理员在 **「邀请记录与状态」** 页签核对该条记录是否为 `expired` 或 `revoked`，点击 **「重新生成邀请」** 后将新链接发给对方。

## 3. 管理员如何修改成员角色或将成员移出工作空间？

- **适用角色**：仅工作空间管理员（`admin`）；`member` 与 `guest` 仅可在 **「个人头像 > 账号与身份」** 查看自身角色，不可修改任何人角色。
- **前提条件**：工作空间内至少保留一名有效的 `admin`（系统禁止将空间内最后一名 `admin` 降级或移出）。
- **页面路径与按钮**：左侧导航栏 **「空间管理 > 成员与邀请」** → **「正式与访客成员列表」** → 成员行右侧 **「修改角色」** / **「移除成员」**。
- **操作步骤**：
  1. 在 **「空间管理 > 成员与邀请 > 正式与访客成员列表」** 中，通过搜索框定位目标成员。
  2. **修改角色**：点击目标成员操作列的 **「修改角色」**，在下拉框中选择新角色（`admin` / `member` / `guest`），并在二次确认弹窗中点击 **「确认变更」**。
     - 若将 `member` 改为 `guest`：系统会立即收回其对未单独授权公开项目的默认访问权，以及所有项目的编辑（`edit`）权限（自动降级为 `read` 或 `comment`）。
  3. **移除成员**：点击目标成员操作列的 **「移除成员」**，在弹窗中选择将其名下负责的项目交接给指定 `admin` 或其他 `member`，点击 **「确认移除」**。
- **预期结果**：角色变更或成员移除即时生效，该成员绑定的 API 凭据权限范围同步按新身份重新校验，且操作自动记入 **「空间管理 > 安全与审计日志」**。
- **失败时的处理方法**：
  - **提示“无法移除该成员，其名下仍有未交接的私有项目”**：请在移除弹窗中指定项目接管人，或先前往 **「空间管理 > 项目全局管理」** 执行 **「接管项目」** 后再移除该成员。

## 4. 如何在项目内创建、协同编辑、批注和共享文档？

- **适用角色**：
  - 创建、编辑文档：`admin`，以及拥有该项目 `edit` 或 `manage` 权限的 `member`。
  - 查看并添加批注/讨论：`admin`，以及拥有该项目 `comment`、`edit` 或 `manage` 权限的 `member` / `guest`（仅拥有 `read` 权限的成员只能阅读，无法编辑或批注）。
- **前提条件**：已具备目标项目的对应访问与操作权限。
- **页面路径与按钮**：**「项目中心 > 目标项目详情页 > 项目文档」** 页签。
- **操作步骤**：
  1. **新建与结构化编辑文档**：进入目标项目的 **「项目文档」** 页签，点击 **「+ 新建文档」**（或点击目录树中的已有文档进入编辑）。在编辑器中输入正文，支持多人实时协同编辑；点击右上角 **「版本历史」** 可查看修改记录。
  2. **发起划词批注、`@` 提及同事与讨论**：
     - **局部批注与 `@` 提及**：选中文档中的具体语句或表格单元格，点击浮现工具栏的 **「添加批注」**，在输入框填写批注内容（可键入 `@` 并从下拉候选框中选择当前项目的协作者，如 `@小林`），然后点击 **「发布」** 按钮；被提及的协作者会在 **「工作台 > 收到的批注提醒」** 中看到提醒，并可在右侧 **「批注栏」** 回复或点击 **「标记为已解决」**。
     - **全局讨论**：在文档底部或项目 **「讨论与批注」** 页签输入评论并点击 **「发布」**，汇总跨文档的协作意见。
  3. **共享项目内文档**：点击文档页面右上角的 **「分享文档」** 按钮，复制文档直达链接发送给团队成员。
     - **重要权限约束**：文档继承其所属项目的访问权限边界，**共享文档链接不会突破已有项目权限**。如果接收人本身没有该项目的访问权，点击文档链接同样会提示无权访问。
- **预期结果**：团队成员在同一文档内完成实时撰写、审阅批注与讨论留痕。
- **失败时的处理方法**：
  - **外部访客（`guest`）反馈能打开文档但无法添加批注**：这是因为该 `guest` 在项目中仅被授予了 **「只读查看（`read`）」** 权限，而 **`read` 权限不自动包含批注权限**。请项目负责人或空间 `admin` 进入 **「项目成员与权限」**，将该 `guest` 的权限等级从 `read` 调整为 **「可批注（`comment`）」**。
  - **普通成员（`member`）尝试删除项目核心文档被拒绝**：为保护团队资产，普通 `member` 不能随意删除他人创建的项目或核心文档；确需清理废弃文档时，需由文档创建者本人、项目负责人（`manage`）或空间管理员（`admin`）执行。

## 5. 如何分享项目？为什么把分享链接发给同事后对方仍然打不开？

### 5.1 分享项目的操作步骤
- **适用角色**：对该项目拥有访问权限的 `admin`、`member`（`guest` 不支持扩大共享范围）。
- **页面路径与按钮**：**「项目详情页」** 右上角 **「分享项目」** 按钮。
- **操作步骤**：进入目标项目详情页，点击右上角 **「分享项目」**，在弹窗中点击 **「复制项目链接与项目标识」**（包含项目访问 URL 与 `project_id`），将其发送给协作者。

### 5.2 “分享链接”、“邀请入空间”与“实际项目授权”的核心区别

在日常协作中，用户最常遇到的问题是：**“我已经把项目链接分享给同事了，为什么他点开还是提示无权限？”**  
这是因为在协作平台中，**邀请加入工作空间**、**分享项目链接**与**授予项目访问权限**是三个完全独立的动作：

| 操作动作 | 实际生效的结果 | 不会自动发生的结果 | 接收方打不开链接时的解决办法 |
| :--- | :--- | :--- | :--- |
| **邀请加入工作空间** | 让受邀人获得空间成员身份（`admin`、`member` 或 `guest`） | `member` 不会自动获得私有项目（`private`）权限；`guest` 不会自动获得任何公开或私有项目权限 | 针对需要协作的私有项目（或 `guest` 需访问的任意项目），单独添加项目协作者或提交 `read` 申请 |
| **分享项目链接/标识** | 仅将项目的访问入口地址和 `project_id` 告知对方 | **分享链接本身绝不自动修改项目权限列表**，普通 `member` 也不能通过发链接突破已有权限边界 | 若项目为 `private`（或接收方为 `guest`），需在 **「项目成员与权限」** 中添加对方，或引导对方点击无权限提示页上的 **「申请只读访问（`read`）」** |
| **添加协作者 / 批准申请** | 在该项目的权限记录中正式写入该用户的 `read`、`comment` 或 `edit` 权限 | 仅对当前单个项目生效，不改变该用户在其他项目中的权限 | 授权写入成功后，接收方再次点击原分享链接即可正常打开项目 |

## 6. 示例：跨角色分享私有项目与文档批注的完整排查

> **示例说明（以下为假设情境，仅供演示操作与排查逻辑，非当前用户真实状态）**：  
> **前提设定**：假设在“智造科技”工作空间中，研发组长老刘（`member`）创建了私有项目“芯片固件升级（`proj_fw_09`）”，并将项目文档链接发给了同组的测试工程师小张（`member`）、外部合规顾问林工（`guest`）以及空间管理员王总（`admin`）。

1. **为什么王总（`admin`）可以直接打开链接，而小张（`member`）和林工（`guest`）打不开？**
   - 王总作为本工作空间的 `admin`，默认拥有本空间内全部公开与私有项目的管理与访问权，因此点击链接可直接查看 `proj_fw_09` 及其文档。
   - 小张虽为 `member`，但 `proj_fw_09` 是私有项目（`private`），老刘仅发送了分享链接而未将小张加入协作者名单；林工作为 `guest`，对任何未明确授权的项目均不可访问。
2. **如何分角色在平台页面完成正确授权？**
   - 小张点击链接后，在无权限提示页点击 **「申请只读访问（`read`）」** 提交申请（或由项目负责人老刘在 **「项目详情页 > 项目成员与权限 > + 添加协作者」** 中直接将小张添加为 `edit` 可编辑）。
   - 老刘需要将林工加入该项目并收集其审阅批注。如果老刘只给林工授予 `read` 权限，林工打开文档后将无法添加批注（因为 `read` 不包含批注权限）；老刘在 **「+ 添加协作者」** 中为林工专门选择 **「可批注（`comment`）」** 权限，林工即可正常阅读文档、选中段落填写批注并点击 **「发布」**，同时无法修改文档正文或向外二次共享。

## 7. 常见问题（FAQ）

### 问：我是正式成员（`member`），为什么在项目详情页里不能把一个私有项目直接改成团队公开（`workspace_public`）？
答：在协作平台中，只有该项目的负责人（拥有该项目 `manage` 权限的创建者）以及本工作空间管理员（`admin`）可以进入 **「项目设置」** 调整项目的可见性范围。如果你只是该私有项目的普通可编辑（`edit`）或只读（`read`）成员，不能自行扩大项目的公开范围；如需调整，请联系该项目负责人或本空间 `admin` 在页面操作。

### 问：同事是外部访客（`guest`），为什么我把团队公开项目（`workspace_public`）的链接发给他，他还是打不开？
答：因为“团队公开项目（`workspace_public`）”仅对本工作空间的管理员（`admin`）和正式成员（`member`）默认可见。访客（`guest`）遵循“仅访问明确授权给自己的项目”原则，公开项目对其同样默认不可见。需要由该项目负责人或本空间 `admin` 进入该公开项目的 **「项目成员与权限 > + 添加协作者」** 将该 `guest` 显式加入（授予 `read` 或 `comment`），或者让该 `guest` 在页面提交该项目的 `read` 访问申请并经该项目负责人或本空间 `admin` 审批通过后，对方才能打开。
